# Borex Solar Engine — Engineering Changelog

This file records sizing-model changes, design decisions, and open questions that require
engineer sign-off before code changes are made. It must not be deleted or auto-generated.

## 2026-09-25 · Battery DoD constant corrected (was 0.8 → now 0.9)

**Severity: Bug / material impact on every battery recommendation produced before this date.**

The Borex engineering document specifies 90 % depth-of-discharge for the lithium
(LiFePO4) batteries Borex installs. The implementation had `0.8` (80 % DoD), which is the
conventional assumption for lead-acid batteries. This was wrong for our lithium fleet.

### Formula before this fix

    battery_kWh = nightEnergy × backupFactor / 0.80

### Formula after this fix

    battery_kWh = nightEnergy × backupFactor / 0.90

### Effect
With the corrected DoD the recommended battery capacity is ~11 % smaller than the
previous (incorrect) output for any given load set.

> WARNING: DO NOT compare saved estimates made before 2026-09-25 directly with estimates
> made after this date without accounting for the DoD change. The old number was
> over-specified; the new number is correct per Borex engineering spec.

### Constant location
`pages/_index.tsx` — BATTERY_DOD = 0.9

## 2026-09-25 · Essential-load vs. whole-house backup mode added

A project-level input now lets the technician choose:

- **Whole-house** (default): all appliances — including occasional loads with night/both
  hours — count toward the nighttime backup energy used to size the battery.
- **Essential-load**: only appliances explicitly marked CRITICAL count toward the
  night backup energy. Occasional appliances are excluded from the battery sizing
  calculation even if they have night hours entered, because they will not be kept on
  battery power during an outage.

The backup mode is shown prominently in the results panel so anyone reading the saved
estimate knows which mode produced the battery figure.

## 2026-09-25 · Budget-tiered recommendations (Option A / B / C) added

When a project has an optional budget figure entered that is below the estimated cost of
the fully-specified system (Option A), the engine generates two additional options by
re-running the deterministic sizing formulas with reduced inputs:

| Option       | Inverter          | Battery      | Solar        | Trade-off disclosed                              |
|--------------|-------------------|--------------|--------------|--------------------------------------------------|
| A            | Full              | Full         | Full         | —                                                |
| B            | Full (unchanged)  | 60 % of A    | 75 % of A    | Shorter backup duration; reduced self-sufficiency|
| C (Phase 1)  | Full (unchanged)  | 50 % of A    | 50 % of A    | Battery and PV added in Phase 2                  |

Rule: the inverter is never reduced in Option B or C. Inverter size is a safety
floor determined by what the client's appliances actually draw at surge; cutting it
would risk tripping or hardware damage. Only battery and solar are reduced.

All three options are generated by the deterministic engine with different parameters.
No AI is asked to "invent" a cheaper system. Reduced-capability disclosures are
displayed inline alongside each option, not in a footnote.

Cost estimation uses approximate market rates (adjustable):
- Inverter: N120,000 per kVA
- Battery (LiFePO4): N180,000 per kWh
- Solar panels + mounting: N100,000 per kWp

## OPEN QUESTION — Motor surge scope (awaiting Borex engineer decision)

**Status: UNRESOLVED — do not change the formula until this is answered.**

### The question
The current peak-surge formula sums ALL appliances' surge demand:

    peak = sum(critical_loads x surge_multiplier)
           + sum(occasional_loads x surge_multiplier) x 0.6

This includes the surge multiplier for every motor in the list simultaneously. In
practice, motors never all start at exactly the same moment. An alternative approach
used by many installers is "largest single motor starting surge" added to the steady-state
running load:

    peak_alternative = steady_state_running_total + max(motor_starting_surges)

The CEO's engineering document does not specify which assumption is correct for
real Borex installations. Neither formula has been validated against a field
measurement from an actual Borex-installed system.

### Decision needed from a Borex installation engineer:
1. Do multiple motors in a typical installation start within the same half-cycle window,
   or are they started sequentially?
2. Is sum-of-all-surges or largest-single-surge-added-to-running-load more accurate?
3. If the answer differs by installation type (residential vs. commercial), does the
   tool need a selector?

### Current behaviour (unchanged until answered)
The tool sums ALL appliances' surge demand. This is the more conservative approach
and will never under-size an inverter, so it is safe to leave in place while
waiting for the field answer.

Do not silently resolve this question in code. Update this file when it is answered.
